# CardForge Risk Register

Last updated: October 26, 2026

Only unresolved or explicitly accepted risks belong here. Closed work belongs in Git/provider history and current operating instructions belong in `docs/operations.md`.

| Area | Risk | Priority | Status / next proof |
| --- | --- | --- | --- |
| Migration provenance | Older provider migration timestamps do not consistently match repository filenames, so an edited or removed historical migration can leave Git and a provider ledger out of sync. | P1 | Controlled. On September 16, authenticated Supabase history and the live schema confirmed that the staging-only `20260912033706` entry was the already-applied Drive resource-key migration tracked in Git as `20260911213000`; the provider ledger was reconciled without changing schema or data. Keep future migrations additive and immutable, compare the production tail before rollout, and never guess from filenames alone. |
| Drive concurrent external edits | Exact revision preflight is not an atomic compare-and-swap against an unrelated writer that changes the same Drive blob after preflight but before the resumable upload commits. | P1 | Open residual provider race. CardForge serializes its own writes, refuses stale browser/MCP commits, pauses autosave on dirty remote changes, queries/resumes interrupted upload sessions before declaring an unknown outcome, moves explicit removals to recoverable Drive Trash, and keeps source-deleting Drive Move disabled. Complete one controlled final-upload overlap against an independent writer before claiming stronger simultaneous-write guarantees. |
| Drive collaborator and invalidation acceptance | Shared-folder/shared-drive permissions, resource keys, reconnect, read-only projection, trashed-source detection, and 30-second shared-file freshness are implemented, but the final real-provider failure matrix is not yet complete. | P1 | Open provider acceptance. Exercise collaborator-created Picker authorization, editor/viewer roles, external move, external rename, file/folder Trash, revoked Google access, same/different-account reconnect, Shared Drive Connected Assets, interrupted resumable upload, and the final-upload overlap race. Current provider content/capabilities win; shared listing is saved-file freshness, not realtime collaboration. |
| Google OAuth environment isolation | Production OAuth is published and uses only non-sensitive `drive.file`, but Preview/testing must remain provider-isolated from production so test revocation, callbacks, and Picker restrictions cannot affect public users. | P1 | Reverify in Google Cloud that Production and Preview use separate Cloud projects, OAuth clients, Picker keys, and token-encryption keys. Production publication itself is complete; this row remains only until environment separation is reconfirmed after the publication pass. |
| Legacy commercial grants | Older private paid metadata does not always distinguish an owner grant from Stripe projection. | P1 | Controlled. Preserve access and require explicit owner grant confirmation; no timestamp inference or automatic destructive migration. |
| Preview developer-plugin acceptance | An installed client can retain an older tool catalogue after the Preview server changes; successful discovery or browser authentication alone does not prove every privileged operation or account transition. | P1 | Open acceptance, issue #444. The publicly reachable Preview website and separate Studio/Owner developer connections now reach CardForge with isolated Development/Staging identity. Actual Studio draft, Set generation, exact-revision edit, stale-write rejection, render and wrong-Contributor-role denial have been exercised. New server tools still require a client invocation that actually exposes their current typed schemas before agent parity can be accepted; do not work around a stale binding with raw backend calls, unrelated reauthentication, or permission changes. Complete remaining account-transition/revocation and per-operation browser/MCP proof. Public marketplace release and Production acceptance remain separate gates. |
| Owner presentation authority | A future code path could bypass canonical Owner commands or reintroduce repository/provider writes that compete with live Owner-authored presentation. | P1 | Controlled in Preview by #407: browser and Owner MCP share canonical publication commands, site-copy writes are revision-safe, production/Preview publication state is explicit, and post-cutover migrations that write Owner presentation require an explicit reviewed rationale marker. Residual work is per-operation compare-and-publish hardening for additional Owner domains before they gain agent mutation tools; keep production provider changes separately gated. |
| Commercial price parity | A configured Stripe Price can become unavailable or change independently of CardForge plan marketing presentation. | P1 | Controlled in Preview by #423: Creator/Designer amount, currency, and recurrence are projected from the configured Stripe Prices at every customer-facing plan boundary; Owner controls retain names/copy/features/visibility/capacity but cannot overwrite paid monetary facts. Unverifiable Stripe pricing fails closed as unavailable and removes the self-serve paid CTA. Reverify the exact production Stripe Price configuration after Main promotion before closing the rollout risk. |
| Billing provider acceptance | Current Stripe projection and additive grants pass focused tests and independent review; the disposable native multi-subscription checkout/reconcile experiment is unfinished. | P2 | Deferred acceptance follow-up. No paid fixture was activated. Preserve current-provider reconciliation and service-owned locking; complete the sandbox journey before a broader billing rollout. |
| Social publishing | A credential, wrong destination, scheduler retry, or partial approval could expose media or publish an unapproved post. | P1 | Open; hard-disabled. Keep extended-contribution/native Meta gates off until protected media, scoped contributors, encrypted tokens, exact destinations, idempotent claim/retry, harmless publication, and durable delivery postflight in `docs/operations.md` pass. Communities remain manual-only. |
| Large local projects | Long artwork sessions can exceed browser quota or degrade recovery despite IndexedDB, persistence requests, actual-write failure reporting, snapshots, and project export/import. Complete-body download/provider boundaries also materialize one size-bounded package Blob, while authorized device-file saves stream. | P1 | Accepted. Browser capacity is not a CardForge allowance and persistence is not a backup. Revisit after a real quota/recovery report or when a provider supports a practical streaming upload contract. |
| Owner site composition and screenshot truth | Site composer inputs or generated screenshots could misstate product capability, expose private signed-in work, break responsive semantics, or introduce arbitrary execution if not constrained. | P1 | Controlled for the accepted Website Editions beta in Preview (#469, [hosted Owner acceptance](https://github.com/pyralisxc/CardForge/issues/469#issuecomment-6387420365)): exact Owner revision activation, changed-image browser decode, guarded rollback, original-image live return, saved-private-image retention and genuine non-Owner Save/Activate denial passed; the Owner accepted the beta, so founder acceptance is **not pending for this tranche**. Owner Composer retains finite validated blocks, exact revision guards and authenticated bounded media slots. The five-stage Set → Design → Generate → live Review → Output showcase uses reviewed non-private product captures and truthful PNG/digital-PDF controls. Residual: independently review future visual-authoring changes, unverified physical-device/nested-provider behavior and new presentation surfaces; never capture private account UI for marketing or allow arbitrary HTML/JS/CSS execution. Preserve broader #469 ownership; this beta proof does not close all Owner/MCP/product acceptance. |
| Print production | A color-managed reference candidate and successful download are not independent standards or professional-workflow acceptance. | P1 | Open acceptance gap tracked by #406. Canonical trim/bleed/safe geometry, production PNGs, sheet/duplex output, source-image detail checks and machine-readable preparation preflight remain distinct from press readiness. The separate local PDF/X-4-target candidate uses opaque white-composited canonical pixels, ICCBased rendered sRGB and an embedded, hash-verified FOGRA39L coated-offset reference; complete profile notices and exact PDF/pixel/geometry reports travel with it. That older reference condition is not universal printer/stock calibration or preconverted CMYK. Independent PDF/X prepress validation and representative professional-workflow acceptance are pending, so pressReady remains false. Do not market certified print-ready output from metadata, parser/render checks or a successful browser download. |
| Export acceptance | Browser success does not prove every downloaded PDF/TTS artifact or simulator import at large-set limits. | P2 | Accepted with manual checks. Inspect affected artifacts and perform a real TTS import after renderer/export changes. |
| Solo maintainer | A PR author cannot independently approve their own change, so one required approval would deadlock releases. | P2 | Accepted while `@pyralisxc` is the only trusted code owner. Keep resolved threads plus CI, Vercel preview, and live workflow checks; require one approval when a second trusted reviewer joins. |
| Provider presentation | A configured Stripe receipt path and Resend reply-to header do not prove one customer receipt email or an inbound reply round trip. | P2 | Manual proof remains. Complete these naturally or with an explicitly approved test; do not mutate a real customer merely to manufacture evidence. |
| Repository security monitoring | GitHub Dependabot security alerts and secret scanning are disabled, and no code-scanning analysis is configured, so the repository has no hosted alerting backstop for newly disclosed dependency or code issues. | P2 | Open founder/provider configuration decision. On September 16, the checked-in production lockfile was independently audited and is clean after the Hono 4.13.8 and current dependency-maintenance updates. Before enabling hosted scanning, confirm the GitHub plan/cost and desired maintainer notification policy; do not represent unavailable scanners as a clean result. |
